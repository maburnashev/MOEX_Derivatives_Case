# Пульс-MOEX: опционы для розничного инвестора

Проект объединяет:

- сбор и обработку данных срочного рынка Московской биржи;
- анализ динамики оборотов и сделок по фьючерсам и опционам;
- оценку связи клиентской активности с оборотами рынка;
- построение прокси-модели комиссионных доходов;
- анализ пользовательского опроса;
- сценарную оценку потенциального прироста клиентов и комиссий;
- формирование продуктовых выводов для MVP.

---

## Идея проекта

Опционы остаются сложным инструментом для массового розничного инвестора. Основные барьеры - непонимание механики инструмента, страх перед риском, отсутствие практики без реальных денег, сложность интерфейсов и неочевидные преимущества опционов по сравнению с более привычными инструментами.

Гипотеза проекта:

```text
маркетинг → понятное обучение → песочница → AI-помощник → визуализация риска → первая сделка
```

## Используемые данные

### 1. Данные MOEX ISS API

В проекте используются данные срочного рынка из MOEX ISS API.

Основной endpoint:

```text
https://iss.moex.com/iss/engines/futures/turnovers.json
```

Из него собираются данные по:

- фьючерсам;
- опционам;
- суммарному срочному рынку.

Основные поля:

- `value_rub_mm` - объем торгов в млн рублей;
- `value_usd_mm` - объем торгов в млн долларов;
- `num_trades` - количество сделок;
- `instrument_type` - тип инструмента: `futures`, `options`, `totals`;
- `date`, `year`, `month`, `quarter` - временные признаки.

### 2. Данные по активным клиентам

Для исторической модели используется таблица активных клиентов брокеров Московской биржи.

Данные собираются из HTML-страниц рейтинга брокеров по активным клиентам.

Основные поля:

- `year`;
- `quarter`;
- `month`;
- `active_clients`;
- `delta_active_clients`.

### 3. Данные пользовательского опроса

В проекте используется CSV-файл с ответами респондентов на опрос о восприятии опционов.

Опрос используется для:

- выделения целевой аудитории;
- оценки барьеров для торговли опционами;
- построения воронки готовности к обучению, песочнице и реальной торговле;
- оценки сценарной конверсии в новых пользователей рынка опционов.

### 4. Финансовые и справочные материалы

Для калибровки комиссионной модели используются:

- данные о комиссионных доходах срочного рынка;
- текущие прокси-данные по комиссиям;
- результаты анализа рыночной активности;
- материалы по продуктовой концепции и MVP.

## Методы проекта

### 1. Парсинг рыночных данных

Данные MOEX ISS API собираются по дням и затем агрегируются до месячного, квартального и годового уровня.

Для каждого периода формируются показатели:

- оборот в рублях;
- оборот в долларах;
- число сделок.

### 2. Парсинг активных клиентов

HTML-парсер загружает страницы рейтинга брокеров Московской биржи и извлекает число активных клиентов.

На основе месячных данных рассчитывается:

- абсолютное число активных клиентов;
- месячное изменение активной клиентской базы.

### 3. Историческая модель активности клиента

На историческом периоде рассчитываются коэффициенты связи между приростом активных клиентов и приростом рыночной активности.

Для фьючерсов и опционов отдельно оцениваются:

- прирост оборота на одного активного клиента;
- прирост числа сделок на одного активного клиента.

Эти коэффициенты используются как модельная оценка активности дополнительного или активированного пользователя.

### 4. Текущая оценка активности

Отдельно рассчитываются коэффициенты на основе более поздних данных рынка.

Они используются как альтернативная оценка активности пользователя на более зрелом рынке и могут применяться в позитивных или стресс-сценариях.

### 5. Прокси-модель комиссионных доходов

Комиссионная модель строится двумя способами:

```text
1. через оборот:
   дополнительная комиссия = дополнительный оборот × комиссия на 1 млн рублей оборота

2. через сделки:
   дополнительная комиссия = дополнительное число сделок × комиссия на одну сделку
```

Для каждого типа инструмента рассчитываются:

- комиссия на 1 млн рублей оборота;
- комиссия на одну сделку;
- скорректированные комиссии после калибровки на фактические данные.

### 6. Анализ пользовательского опроса

Опрос анализируется в двух направлениях.

#### Воронка

Воронка строится не по всей выборке, а по целевому сегменту:

```text
активные инвесторы, которые пока не торгуют опционами
```

Этапы воронки:

- активные инвесторы без опыта торговли опционами;
- готовность пройти обучение;
- готовность использовать песочницу;
- готовность перейти к реальной торговле;
- потенциальные новые пользователи опционов.

#### Барьеры и драйверы

Вопросы с множественным выбором анализируются отдельно:

- каждый вариант ответа считается отдельным сигналом;
- один респондент может попасть в несколько категорий;
- суммы долей по таким вопросам могут превышать 100%.

## Описание директорий и файлов

### `data/`

Основная директория с данными проекта.

### `data/daily/`

Содержит дневные данные срочного рынка, полученные через MOEX ISS API.

Типы файлов:

- `entire_turnovers_*.csv` - все строки по срочному рынку;
- `futures_turnovers_*.csv` - только фьючерсы;
- `options_turnovers_*.csv` - только опционы;
- `total_turnovers_*.csv` - суммарный срочный рынок.

Эти файлы используются как базовый слой данных для дальнейшей агрегации.

### `data/analytics/`

Содержит агрегированные данные по оборотам и сделкам.

Типы файлов:

- `monthly_turnovers_*.csv` - месячные обороты и сделки;
- `quarterly_turnovers_*.csv` - квартальные обороты и сделки;
- `yearly_turnovers_*.csv` - годовые обороты и сделки.

Основные поля:

- `instrument_type`;
- `year`;
- `month` или `quarter`;
- `value_rub_mm`;
- `value_usd_mm`;
- `num_trades`.

Эти таблицы используются для анализа динамики рынка, построения графиков и расчета коэффициентов активности.

### `data/clients/`

Содержит данные по активным клиентам брокеров.

Основной файл:

```text
active_clients.csv
```

Содержит:

- год;
- квартал;
- месяц;
- число активных клиентов;
- изменение числа активных клиентов относительно предыдущего месяца.

Используется в исторической модели для оценки связи между ростом клиентской базы и ростом активности срочного рынка.

### `data/model_params/`

Содержит JSON-файлы с ключевыми параметрами моделей.

Эта директория важна, потому что в ней сохраняются итоговые коэффициенты, которые затем используются в финальных расчетах и презентации.

## JSON-файлы в `data/model_params/`

### `client_params.json`

Содержит коэффициенты активности клиента.

Файл описывает, сколько оборота и сделок приходится на одного дополнительного или активированного пользователя.

Структура файла:

```text
description
data
```

#### `description`

Содержит текстовое описание каждого параметра.

Описывает:

- что означает коэффициент;
- к какому инструменту он относится;
- рассчитан ли он на историческом периоде или на более позднем рыночном срезе;
- измеряется ли он через оборот или через число сделок.

#### `data`

Содержит численные значения коэффициентов.

Основные группы параметров:

- `value_rub_mm_growth_per_client_forts` - оценка прироста оборота фьючерсов на одного клиента.
- `num_trades_growth_per_client_forts` - оценка прироста числа сделок по фьючерсам на одного клиента.
- `value_rub_mm_growth_per_client_options` - оценка прироста оборота опционов на одного клиента.
- `num_trades_growth_per_client_options` - оценка прироста числа сделок по опционам на одного клиента.
- `value_rub_mm_growth_per_client_option_real` - альтернативная оценка активности пользователя по опционам на основе более позднего рыночного среза.
- `num_trades_growth_per_client_option_real` - альтернативная оценка числа сделок по опционам на основе более позднего рыночного среза.
- `value_rub_mm_growth_per_client_future_real` - альтернативная оценка активности пользователя по фьючерсам на основе более позднего рыночного среза.
- `num_trades_growth_per_client_future_real` - альтернативная оценка числа сделок по фьючерсам на основе более позднего рыночного среза.

Назначение файла:

```text
используется для расчета дополнительного оборота и числа сделок
при сценарном приросте пользователей рынка опционов
```

### `commission_params.json`

Содержит параметры комиссионной модели.

Файл нужен для перевода дополнительного оборота или дополнительных сделок в потенциальный комиссионный доход.

Структура файла:

```text
description
data
```

#### `description`

Содержит пояснения к каждому комиссионному коэффициенту.

Обычно описывает:

- комиссию на 1 млн рублей оборота;
- комиссию на одну сделку;
- различие между фьючерсами и опционами;
- исходные и скорректированные значения;
- метод калибровки.

#### `data`

Содержит численные значения комиссионных коэффициентов.

Основные типы параметров:

- `fee_per_1m_forts` - исходная оценка комиссии на 1 млн рублей оборота для фьючерсов.
- `fee_per_1m_options` - исходная оценка комиссии на 1 млн рублей оборота для опционов.
- `fee_per_trade_forts` - исходная оценка комиссии на одну сделку для фьючерсов.
- `fee_per_trade_options` - исходная оценка комиссии на одну сделку для опционов.
- `corr_by_value` - корректирующий коэффициент для модели через оборот.
- `corr_by_num_trades` - корректирующий коэффициент для модели через число сделок.
- `fee_per_1m_forts_corr` - скорректированная комиссия на 1 млн рублей оборота для фьючерсов.
- `fee_per_1m_options_corr` - скорректированная комиссия на 1 млн рублей оборота для опционов.
- `fee_per_trade_forts_corr` - скорректированная комиссия на одну сделку для фьючерсов.
- `fee_per_trade_options_corr` - скорректированная комиссия на одну сделку для опционов.

Назначение файла:

```text
используется для оценки дополнительного комиссионного дохода
через оборот и через число сделок
```

### `kd_growth_params.json`

Содержит итоговые оценки прироста комиссионного дохода на одного пользователя.

Файл объединяет параметры из:

- `client_params.json`;
- `commission_params.json`.

Структура файла:

```text
description
data
```

#### `description`

Содержит пояснение, как интерпретировать итоговые коэффициенты.

Обычно описывает:

- прирост комиссионного дохода через оборот;
- прирост комиссионного дохода через сделки;
- различие между фьючерсами и опционами;
- различие между консервативной и более позитивной оценкой.

#### `data`

Содержит итоговые коэффициенты комиссионного эффекта.

Типы параметров:

- `kd_growth_value_option` - оценка прироста комиссионного дохода по опционам на одного пользователя через оборот.
- `kd_growth_num_trades_option` - оценка прироста комиссионного дохода по опционам на одного пользователя через сделки.
- `kd_growth_value_future` - оценка прироста комиссионного дохода по фьючерсам на одного пользователя через оборот.
- `kd_growth_num_trades_future` - оценка прироста комиссионного дохода по фьючерсам на одного пользователя через сделки.

Также могут храниться версии коэффициентов, рассчитанные на основе более поздних рыночных данных.

Назначение файла:

```text
используется как финальный слой параметров для сценарной оценки
прироста комиссионного дохода
```

### Как связаны JSON-файлы

Логика использования:

```text
client_params.json
        ↓
оценивает дополнительный оборот и сделки на пользователя

commission_params.json
        ↓
оценивает комиссию на 1 млн рублей оборота и на одну сделку

kd_growth_params.json
        ↓
объединяет два блока и показывает комиссионный эффект на пользователя
```

Иными словами:

```text
активность пользователя × ставка комиссии = прирост комиссионного дохода
```

## `src/`

Содержит основной код и аналитические ноутбуки проекта.

### `src/parser_json.py`

Парсер данных MOEX ISS API.

Что делает:

- проходит по календарным датам;
- запрашивает данные из `turnovers.json`;
- выделяет `futures`, `options`, `totals`;
- приводит данные к единому формату;
- сохраняет дневные CSV-файлы;
- строит месячные, квартальные и годовые агрегаты;
- сохраняет агрегированные таблицы в `data/analytics/`.

### `src/parser_html.py`

Парсер активных клиентов брокеров.

Что делает:

- загружает HTML-страницы рейтинга брокеров;
- находит таблицу с числом активных клиентов;
- очищает числовые значения;
- суммирует активных клиентов;
- формирует месячную таблицу;
- рассчитывает изменение активных клиентов;
- сохраняет результат в `data/clients/active_clients.csv`.

### `src/analysis_2015-2021.ipynb`

Ноутбук для исторического анализа.

Что содержит:

- загрузку агрегированных данных 2015–2021;
- объединение рыночных данных с данными активных клиентов;
- расчет прироста оборотов, сделок и клиентов;
- расчет исторических коэффициентов активности клиента;
- сохранение параметров в `client_params.json`.

### `src/analysis_2022-2026.ipynb`

Ноутбук для анализа современного периода и комиссионной модели.

Что содержит:

- загрузку данных 2022–2026;
- анализ динамики фьючерсов и опционов;
- расчет текущих коэффициентов активности;
- расчет прокси-комиссий через оборот и сделки;
- калибровку комиссионных ставок;
- сохранение параметров в `commission_params.json`.

### `src/analysis_poll.ipynb`

Ноутбук для анализа пользовательского опроса.

Что содержит:

- загрузку данных опроса;
- очистку и подготовку ответов;
- выделение целевого сегмента;
- анализ барьеров и условий перехода к опционам;
- расчет воронки;
- расчет сценарных конверсий;
- подготовку визуализаций для презентации.

### `src/results.ipynb`

Финальный расчетный ноутбук.

Что содержит:

- загрузку JSON-файлов с параметрами;
- объединение коэффициентов активности и комиссионных ставок;
- расчет прироста комиссионного дохода на пользователя;
- сравнение оценок через оборот и через сделки;
- сохранение итоговых коэффициентов в `kd_growth_params.json`.

### `main.py`

Файл-заглушка или точка входа для будущего воспроизводимого запуска проекта.

На текущем этапе основная логика проекта выполняется через ноутбуки и отдельные парсеры.

Возможное будущее назначение:

- запуск парсеров;
- обновление данных;
- пересчет агрегатов;
- пересчет модельных параметров;
- формирование итоговых таблиц.

## Ограничения

1. Опросная выборка ограничена и может быть смещена.
2. Результаты опроса отражают намерения пользователей, а не фактическое поведение.
3. Историческая модель использует прирост активных клиентов как proxy для оценки эффекта от привлечения или активации пользователя.
4. Комиссионная модель является proxy-оценкой, так как публичная детализация комиссий по опционам ограничена.
5. Текущие коэффициенты активности могут быть чувствительны к рыночной волатильности.
